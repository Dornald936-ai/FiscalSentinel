# Fiscal Sentinel

**AI-powered financial intelligence for rural district councils.**

> Most systems tell councils what happened. Fiscal Sentinel tells them what needs attention next.

Fiscal Sentinel watches a district council's revenue collections across wards
and revenue streams, scores each one for financial risk, forecasts the next
quarter's collections, and turns the findings into a short, plain-language
brief for the finance committee.

Detected events are always described as **financial anomalies** or
**potential revenue leakage** - the system flags patterns that need
verification, never accusations of fraud.

---

## What it does

- **Detects revenue anomalies** - a Financial Risk Score (0-100) per ward and
  revenue stream, combining revenue deviation, historical abnormality
  (statistics + an Isolation Forest), transaction pattern anomalies (receipt
  volume vs. revenue divergence, round-number banking), and peer-ward
  comparison. Genuine seasonal dips are explicitly recognised and never
  flagged.
- **Forecasts collections** - a 3-month, per-revenue-stream forecast with a
  95% confidence range, built from a deseasonalised damped-trend model and
  compared against budget.
- **Explains risk in plain language** - a "Generate Financial Brief" button
  turns the Python-computed findings into an executive summary. If no LLM API
  key is configured, the brief is generated deterministically from the same
  findings, so the demo never breaks.

## Stack

- **Backend:** Python, FastAPI, Pandas, NumPy, scikit-learn (Isolation
  Forest), statsmodels (forecasting). Data lives in a CSV file - no
  database required.
- **Frontend:** React (Vite), Tailwind CSS v4, Recharts, Axios.
- **AI layer:** the LLM (Claude, via the `anthropic` package) only turns
  Python-computed findings into prose. It never calculates a number - every
  figure in a brief comes from `analytics.py` / `forecast.py`.

## Setup (PowerShell)

### 1. Backend

From the project root:

```powershell
# Create and activate a virtual environment (skip if .venv already exists)
py -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install dependencies
pip install -r requirements.txt

# Generate the synthetic council dataset
python backend\generate_data.py

# Optional: run the analytics and forecast engines standalone to see
# their self-checks pass before starting the API
python backend\analytics.py
python backend\forecast.py
python backend\brief.py
```

### 2. Frontend

In a separate PowerShell window, from the project root:

```powershell
cd frontend
npm install
```

A `frontend\.env` file is already set up pointing the dashboard at
`http://localhost:8000`. Change `VITE_API_URL` there if you run the backend
on a different port.

---

## Running it

**Backend** (from the project root, with the venv active):

```powershell
.\.venv\Scripts\Activate.ps1
cd backend
uvicorn main:app --reload --port 8000
```

The API is now at `http://localhost:8000` (interactive docs at
`http://localhost:8000/docs`).

**Frontend** (in a second terminal):

```powershell
cd frontend
npm run dev
```

Open `http://localhost:5173` in a browser.

## Enabling the AI-written brief (optional)

Without any configuration, "Generate Financial Brief" produces a
deterministic, template-based brief from the same Python-computed findings -
this is what ships by default and what the demo relies on.

To have a language model write the narrative instead, set an environment
variable **before starting the backend** - the key is read from the
environment only and is never hardcoded or logged:

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
cd backend
uvicorn main:app --reload --port 8000
```

Optional: override the model (defaults to `claude-opus-5`):

```powershell
$env:FISCAL_SENTINEL_MODEL = "claude-opus-5"
```

If the key is missing, invalid, or the request fails for any reason, the API
automatically falls back to the deterministic template brief - the "Generate
Financial Brief" button always returns something.

## API reference

| Endpoint | Method | Description |
|---|---|---|
| `/api/health` | GET | Service status and books monitored |
| `/api/kpis` | GET | The 5 headline KPI cards |
| `/api/anomalies` | GET | Every ward/revenue-stream book, risk-sorted (the Financial Risk Radar) |
| `/api/anomalies/{id}` | GET | One book's full detail, including its actual-vs-expected trend series |
| `/api/forecast` | GET | District-wide and per-stream 3-month forecast vs. budget |
| `/api/brief` | POST | Generate the executive brief (`{"top_n": 5}`) |

Full interactive documentation: `http://localhost:8000/docs`.

## The injected demo scenarios

`generate_data.py` seeds three deliberate patterns so the analytics engine
has something real to find:

1. **Ward 4, Market Fees** - collections drop ~47% from March 2026, while
   receipt volume holds steady (classic revenue-leakage signature). Scores
   **Critical**.
2. **Ward 7, Business Licenses** - an unexplained spike in April 2026, not
   matched by receipt volume. Scores **High**.
3. **Collector COL-024 (Ward 6, Beer Hall Levies)** - suspiciously frequent
   round-number monthly totals. Flagged as a records/controls concern.

Every other book tracks its seasonally-adjusted expectation and stays in the
**Normal** band, including streams with large *raw* seasonal swings (e.g.
Business Licenses' January renewal spike) - the engine is built specifically
not to flag expected seasonality as risk.
